# 项目说明文档

## 一、作品概况

| 项目 | 内容 |
| --- | --- |
| 作品名称 | 字块冲刺 · 英文打字闯关小游戏 |
| 作品路线 | 路线 B：小游戏（学习类 · 打字练习） |
| 运行环境 | 浏览器（Chrome / Edge），双击 `index.html` 即可运行 |
| 技术栈 | HTML + CSS + 原生 JavaScript，无框架、无构建、无后端 |
| 代码仓库 | https://github.com/lcx-lm/typing-block-sprint |

## 二、选题理由

1. **学习类和打字练习是课程明确鼓励的方向。** 作业要求在「学习类小游戏」中列出了键盘指法练习、打单词等方向，并强调要有计分、难度与反馈，而不是「选择题一页页往后翻」。
2. **打字是软件工程专业的高频刚需。** 背单词与英文输入几乎每天都要用，把两者合并成「在下落方块落地前敲完单词」，能同时练拼写速度和单词记忆。
3. **玩法闭环天然适合小游戏。** 下落 + 打字 + 连击 + 关卡，天然具备开始、进行、结束、计分、重开这一整套循环。
4. **技术边界可控。** 纯前端即可实现，不需要服务器与账号体系，能在教师机上双击运行，符合「别人拿去就能用」的交付标准。

## 三、目标用户

- 正在准备四六级、考研，需要反复记忆单词的在校学生。
- 想练英文盲打速度、又觉得单纯打字软件枯燥的同学。
- 想在课间用 2~5 分钟做一个短时训练的人（每关 50 秒，随时可停）。

## 四、功能结构

页面共四个屏幕，加两个弹窗：

| 屏幕 | 主要功能 |
| --- | --- |
| 首页 HOME | 昵称、段位徽章与段位说明弹窗、最高分 / 最佳手速、三种模式入口、最近表现趋势图（右上角「查看详细」打开全部成绩记录）、错词本（含「复习错词」入口）、设置、帮助 |
| 选择 SELECT | 7 套词库、3 档难度；单机模式显示关卡网格（逐关解锁），冲刺 / AI / 错词复习模式隐藏关卡并切换开始按钮 |
| 对局 PLAYING | 单机：关卡进度、本关目标分、50 秒倒计时；冲刺 / AI / 错词复习：60 秒单局，AI 模式显示对手分数；方块下落、前缀高亮、连击、得分飘字、3 颗爱心、暂停 |
| 结算 RESULT | 单页呈现：大字结论统一逐字从上方掉落（失败 / 破纪录 / 全部通关 / 胜利等先停顿约 0.6 秒再依次落下；单机失败时上方居中先显示「第 N 关」），数据区按模式切换——单机显示得分 / 准确率 / 手速 / 最高连击，冲刺显示「破纪录 / 未破纪录」+ 得分 / 最佳手速，AI 对战显示胜利 / 失败 + 你与 AI 的左右对比表（得分 / 最高连击 / 剩余爱心）+ 本局打错单词；下方直接内嵌本局积分——等大字落地后「本局总计积分 ±N」先弹出，金色发光进度条再从结算前的位置前进 / 后退到结算后进度，右侧补间显示当前总积分与段位名，最后揭示 X/100 与距下一段位文案，再往下是再来一局 / 换词库 / 返回首页 |
| 设置弹窗 | 音效开关、主题切换、重新观看新手引导、重置全部数据 |
| 帮助弹窗 | 规则、键位、关卡与生命说明、三种模式与段位积分说明 |

三种模式均已接入实际逻辑；AI 对战为本地模拟对手，不涉及联网。

## 五、核心规则

### 5.1 玩法

方块从顶部下落，方块上是一个英文单词，下方居中显示中文释义。玩家敲出完整单词即可消除方块；已输入的部分会在方块上高亮。方块落到底部则碎掉一颗爱心。

### 5.2 生命

- 每关开始时重置为 3 颗爱心。
- 方块触底：碎 1 颗爱心，该方块移除，连击归零。
- 打错字母：只清空连击，**不扣爱心**。
- 3 颗爱心碎完或时间耗尽，本局结束。

### 5.3 计分

```
单次消除得分 = 单词长度 × 10 × 难度系数 × (1 + 连击数 × 0.1)
```

难度系数：简单 0.8 / 普通 1.0 / 困难 1.3。连击越高，单次得分越高，敲错即归零。

### 5.4 关卡

- 关卡数不写死，由词库词数计算：`ceil(词数 / 8)`，限制在 6~50 关。
- 每关限时 50 秒，达到本关目标分即过关，自动进入下一关。
- 通关后弹出与结算页同格式的祝贺界面：上方居中「第 N 关」，下方绿色「通关」大字逐字从上方掉落（最后一关为「全部通关」），再往下是四张卡片（本关得分 / 本关用时 / 手速 / 下一关目标），伴随礼炮彩带与通关音效；玩家可选择「进入下一关」或「退出」。
- 目标分按「本关词池平均词长 × 目标词数 × 连击加成」计算；目标词数随关卡递增。按实测校准后，四级普通难度第 1 关约 6 个词（约 490 分），最后一关约 11 个词（约 1360 分）。
- 进入选择页时只有第 1 关可选，其余锁定；通关后解锁下一关，并在按钮上标记 ✓。
- 解锁进度按「词库 + 难度」分别保存在本地，退出重进仍然保留；已通关的关卡可以重玩。

### 5.5 难度

| 难度 | 方块生成间隔 | 下落速度 | 单词长度上限 |
| --- | --- | --- | --- |
| 简单 | 2200 ms | 30 px/s | 5 |
| 普通 | 1600 ms | 45 px/s | 8 |
| 困难 | 1100 ms | 65 px/s | 12 |

### 5.6 错词本与错词复习

- 打错字母时，被判定为输入目标的单词会记入错词本，同一单词累计错误次数，每个词库最多保留 120 个。
- 错词本按词库分别保存，首页可查看最近 8 个错词及中文释义，可一键清空当前词库的记录。
- 对局中，错词本里的单词有约 35% 的概率优先出现，仍受当前难度单词长度上限约束。
- 首页错词本标题旁新增「复习错词（N）」按钮：点击后直接用当前词库的错词开一局 60 秒复习。复习局有 3 颗爱心、无关卡目标、不计入成绩记录、不计段位积分，结算显示本局打掉的错词数。
- 复习局按错词数量调节节奏：错词少于 6 个时出块间隔按比例放大（1 个词约 3 倍、3 个词约 2 倍），并且词池中的词若已全部在屏上，则本轮不再出块，避免同屏出现两个相同单词。

### 5.7 模式与段位

**三种模式**

| 模式 | 单局时长 | 规则 |
| --- | --- | --- |
| 单机闯关 | 每关 50 秒 | 选关挑战，达到目标分过关并解锁下一关 |
| 限时冲刺 | 60 秒 | 整库词池，无关卡目标，3 颗爱心耗尽或时间用完结束 |
| AI 对战 | 60 秒 | 左右双跑道，AI 拟人打字；爱心、拔河条压制或时间到比分决定胜负 |

**AI 对战规则**

- 玩家在左、AI 在右，两条跑道各自出块、各自下落，玩家输入只作用于左侧跑道。
- AI 有 3 颗爱心，会先读词再逐字输入；每个词有概率打错，打错时方块变红并显示「✕ 打错了」，随后停顿并清空连击；方块触底会扣 AI 爱心并停顿。
- AI 每个词还有小概率走神，整词漏看：方块显示「✕ 漏看了」并正常下落，落地扣 AI 爱心。普通难度每词约 12%，简单约 20%，困难约 6%。这条机制让「AI 爱心碎完」成为真正可能发生的结局，而不是纸面规则。
- 顶部拔河条按双方分数占比推进：15 秒后且双方总分达到 400 分，一方占比达到 70% 并保持 3 秒即压制获胜；回落到 65% 以下解除读秒。
- 任一方 3 颗爱心碎完立即判负；60 秒结束仍未分出胜负时按比分判定，同分为平局。
- AI 的读词反应、打字速度与失误率随难度变化：简单更慢、失误更多；困难更快、失误更少。

**段位积分**

段位门槛：青铜 0 / 白银 100 / 黄金 300 / 铂金 600 / 钻石 1000。每局结束按模式结算积分：

| 模式 | 积分规则 |
| --- | --- |
| 单机闯关 | 全部通关 +30；通过 3 关及以上 +20；通过 1–2 关 +5；一关未过 −10；每首次通过一关额外 +10 |
| 限时冲刺 | 600 分及以上 +15；400–599 分 +5；低于 400 分 −8 |
| AI 对战 | 获胜 +20；平局 +5；失败 −10（胜负以爱心、拔河条压制或时间到比分判定为准） |

积分最低为 0，不会扣成负数。首页段位徽章右上角的「!」按钮可打开段位弹窗，查看当前段位、积分、距下一段位的进度条、胜负战绩与完整规则；积分跨过门槛时会提示段位提升。

### 5.8 成绩历史与趋势

每局结束（错词复习除外）会把得分、手速、准确率、模式与日期写入本地历史，最多保留最近 20 局。首页「最近表现」面板用内联 SVG 折线画出最近 10 局的得分走势，并显示「近 N 局 · 最高 X · 平均 Y」。图中有横轴（时间先后，标注首/中/末三局日期）、纵轴（分数刻度与横向网格线）、金色平均虚线，鼠标悬停或键盘 Tab 聚焦某个数据点时浮出该局得分与日期气泡。不足 2 局时显示占位提示。它只反映本机数据，换设备或清缓存后不可恢复。

### 5.9 AI 对手设计：带随机扰动的智能体

AI 对战里的对手不是联网模型，也不是按秒匀速加分的计时器，而是一个用「感知 → 决策 → 行动 → 反馈」闭环实现的本地智能体（Agent）。

**1. 智能体四要素**

| 要素 | 在本作中的实现 |
| --- | --- |
| 感知 Perception | 每帧扫描自己跑道的方块集合，读取方块的位置、单词内容与已输入进度 |
| 决策 Decision | 用「最紧急优先」的贪心策略选择目标：位置最低（最接近落地）的方块优先处理 |
| 行动 Action | 先进入读词状态（反应延迟），再按固定字符速度逐字输入，直至消除方块 |
| 反馈 Feedback | 消除得分并累积连击；打错清空连击并停顿；走神或漏词导致方块落地则扣爱心 |

**2. 有限状态机**

```
等待 ──发现方块──> 读词中 ──反应时间到──> 输入中 ──逐字完成──> 等待
                    │                      │
                    │                      ├─概率打错─> 打错了(停顿) ─> 重新输入
                    │                      └─方块落地─> 掉块停顿(扣心)
                    └─概率走神(整词放弃)──> 走神 ─> 等待，方块自然落地扣心
```

状态同时展示在 AI 跑道顶部（等待 / 读词中 / 输入中 / 打错了 / 走神 / 掉块停顿），玩家可以直接观察到 AI 的「思考过程」，而不是只看到一个不断上涨的分数。

**3. 随机扰动：用概率模拟人的不稳定**

| 参数（普通难度） | 取值 | 模拟的人类行为 |
| --- | --- | --- |
| 读词反应时间 | 1.0–1.5 秒随机 | 看到单词到开始敲键的反应 |
| 打字速度 | 2.6 字符/秒 | 普通人的击键速度，而非瞬间完成 |
| 每词打错概率 | 18% | 手误，需要停顿重打 |
| 每词走神概率 | 12% | 注意力不集中，整词漏看 |
| 掉块后停顿 | 1.3 秒 | 失误后的调整时间 |

简单难度更慢、失误更多（打错 22%、走神 20%），困难难度更快、更稳（打错 10%、走神 6%）。因此 AI 的分数是「阶梯式」增长的，玩家能抓住它打错和走神的窗口反超，这是旧版匀速加分无法提供的对局体验。

**4. 与课程内容的对应**

- **智能体（Agent）概念**：感知环境、依据策略选择行动、根据结果改变自身状态。
- **有限状态机**：用显式状态与转移条件描述行为，便于推理与调试。
- **贪心 / 启发式策略**：每次选择「最紧急」的目标，是一种可解释的局部最优决策。
- **随机数与概率模拟**：用可控的随机扰动逼近人的不稳定表现。
- **词库即课程内容**：内置「AI 术语」词库，把智能体、机器学习等课程概念本身作为练习文本。

**5. 边界说明**

AI 对手不调用任何在线大模型、不联网、不学习玩家行为，也不保存对局之外的状态。它是确定性的规则 + 可控随机数，优点是离线可运行、行为可解释、参数可调；代价是它不会像真人一样针对玩家调整策略。

## 六、使用方法

1. 解压后双击 `index.html`，用 Chrome 或 Edge 打开，无需安装、无需联网。
2. 首次进入先填写昵称，随后是 7 步新手引导，可随时跳过。
3. 首页选择模式：「单机闯关」需再选词库、难度、关卡；「限时冲刺」「AI 对战」只需选词库与难度；「复习错词」直接用当前词库的错词开局。
4. 键位：字母 / 数字键输入；`Backspace` 清空当前输入；`Esc` 暂停或继续，暂停弹层中可点「退出本局」直接回到首页，不再展示结算页（积分与成绩仍按规则在后台结算；AI 对战中退出视为认输）。开局后一个单词都没消除就退出不扣积分；已有消除记录时先弹出确认框，显示目前已消除的分数、再消除多少个单词即可通过本关、以及现在退出会扣除的积分，取消则继续暂停；点击页面确保获得键盘焦点。
5. 请使用英文输入法；检测到输入法组合输入时会提示并暂停判定，避免吞键误判。
6. 结算为单页：大字显示本局结论（胜利 / 失败 / 破纪录 / 全部通关 等，统一先停顿约 0.6 秒再逐字从上方掉落到位；单机失败时先只显示居中的「第 N 关」）与本局得分、准确率、手速、最高连击、错词；只有刷新个人最高分时才显示破纪录徽章，不再显示「未破纪录」。数据区下方直接展示本局积分：等大字落地后「本局总计积分 ±N」先弹出（加分金色、扣分红色），金色发光进度条再从结算前的进度前进 / 后退到结算后进度，右侧总积分从原有值补间到结果值，走条结束后揭示当前段位名与「距下一段位还差 N 分」，底部直接选择「再来一局」「换词库」或返回首页，不再需要点「下一步」。

## 七、技术实现简述

- **结构**：单页应用，通过 `body[data-state]` 与 `.screen.is-active` 切换四个屏幕，路由集中在 `main.js`。
- **脚本加载顺序**：`words.js → storage.js → ui.js → game.js → main.js`，均为普通 `<script>`，不使用 ES Module，因此 `file://` 协议可直接运行。
- **游戏循环**：`requestAnimationFrame` 驱动，方块为绝对定位的 DOM 节点；输入采用前缀匹配，只有输入是某个方块单词的前缀时才高亮。
- **计分与关卡**：关卡在开局时按词库动态生成（词池切分、目标分、时间），不写死在代码里。
- **持久化**：`storage.js` 统一封装 `localStorage`，键名带 `typingBlock_` 前缀；不可用时降级为内存存储并提示一次。
- **词库**：四级、六级、考研、小学、高中五套由 ECDICT（MIT License）按考试标签筛选、按词频排序、清洗释义后生成；代码关键字与 AI 术语为自建示例。全部内嵌为静态数据，运行时不需要联网或调用 API，共约 2200 词。
- **音效**：Web Audio API 实时合成，没有外部音频文件，因此不需要处理音频素材版权。

本地存储键：`nickname`、`bestScore`、`bestWpm`、`settings`、`helpSeen`、`guideSeen`、`levelProgress`、`wrongBook`、`rankPoints`、`rankRecord`、`history`，统一前缀 `typingBlock_`。

## 八、局限与已知问题

1. 仅支持英文与数字输入，不支持中文输入法组词上屏。
2. 未做移动端触屏键盘适配，小屏只保证页面可滚动、游戏区不被遮挡。
3. AI 对战为本地规则模拟对手，按反应时间、打字速度与失误率行动，不是真实模型或联网玩家。
4. 无后端，成绩记录、段位与积分只存在本地，换设备或清缓存后不可恢复。
5. 词库为离线静态数据，不随远程自动更新；长对局仍可能出现重复单词。
6. 目标分为按公式估算，未按真实玩家水平做动态难度调节。
7. 错词本只记录「打错字母时锁定的目标单词」，无法区分手误与真正不会的单词。
